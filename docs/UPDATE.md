# 更新機制

所有 app 用同一套規則檢查與安裝新版本。畫面怎麼呈現見 [UI.md](UI.md)。

## 1. 檢查：`latest.json`

```
https://github.com/zoosewu/<repo>/releases/latest/download/latest.json
```

- 這是 GitHub 官方文件記載的「最新 Release 檔案」固定網址，**不經過 GitHub API，沒有每小時 60 次的額度限制**。
- `latest` 不含草稿與預先發行版。
- 只送出一個 GET 請求，不帶任何使用者資料。

### 格式（相容 Tauri updater）

```jsonc
{
  "version": "0.7.0",                          // 不含 v
  "notes": "### 新功能\n- …",                   // git-cliff 產生的說明
  "pub_date": "2026-11-27T08:00:00Z",           // RFC 3339
  "platforms": {
    "windows-x86_64": {
      "url": "https://github.com/zoosewu/<repo>/releases/download/v0.7.0/<檔名>",
      "signature": "<.sig 檔的內容>",           // Tauri／minisign 格式（base64）
      "sha256": "<64 個十六進位字元>"           // zoo-release 擴充欄位
    }
  }
}
```

- 平台鍵：`<OS>-<ARCH>`，OS 為 `windows`、`darwin`、`linux`，ARCH 為 `x86_64`、`aarch64`。
- Docker 專案的 `platforms` 是空物件，只用 `version`。
- 讀取端**略過不認得的欄位**，之後新增欄位不會影響舊版 app。

## 2. 什麼時候檢查

| 時機 | 規則 |
|---|---|
| 啟動 | 啟動 1 分鐘後檢查一次；距上次**成功**檢查不到 24 小時就沿用上次的結果 |
| 長時間開著 | 每 24 小時檢查一次 |
| 手動 | 「關於」頁的「檢查更新」，不受 24 小時限制 |
| 關閉自動檢查 | 「關於」頁的開關，預設開啟；關閉後只有手動檢查 |

## 3. 要不要提示

比較 `version` 與目前版本（`主.次.修補`；預先發行版、格式錯誤的版本都視為沒有新版）：

| 新版本 | 主畫面 | 「關於」頁 |
|---|---|---|
| 主版或次版較新（`0.6.4 → 0.7.0`） | **橫幅提示**（除非已略過） | 顯示「有新版本」 |
| 只有修補版較新（`0.6.4 → 0.6.5`） | 不提示 | 顯示「有新版本」 |
| 相同或較舊 | 不提示 | 顯示「已是最新版」 |

- **略過**：橫幅的「略過此版本」記下 `主.次`。略過 `0.7` 後，`0.7.x` 都不在主畫面提示；`0.8.0` 照常提示。「關於」頁永遠顯示真實狀態。
- **稍後**（關閉橫幅）：這次執行期間不再顯示，下次啟動再提示。

## 4. 下載與安裝（使用者按了才做）

1. 依目前平台從 `platforms` 取得檔案；沒有對應的平台就改為開啟 Release 頁面。
2. 下載，顯示進度，可以取消。
3. **驗證簽章**（必須通過），再驗證 `sha256`（有提供時）。任何一項失敗都刪除檔案、顯示錯誤，並提供 Release 頁面連結讓使用者手動下載。
4. **不允許降版**：下載的版本必須大於目前版本。
5. 安裝：

| 類型 | 方式 |
|---|---|
| Tauri | updater 外掛的下載與安裝，完成後提示重新啟動 |
| 安裝檔（zoo-type） | 執行安裝檔（靜默模式），結束目前程式 |
| 免安裝 exe（z-overlay） | 下載到暫存檔，結束時替換執行檔並重新啟動 |
| zip（zing） | 解壓到暫存資料夾，結束時替換並重新啟動 |

只接受 `https://github.com/zoosewu/<repo>/releases/download/` 開頭的下載網址。

## 5. 錯誤處理

| 情況 | 自動檢查 | 手動檢查 |
|---|---|---|
| 沒有網路、逾時、HTTP 錯誤 | **不顯示**，下次再試 | 「關於」頁顯示「檢查失敗」與重試 |
| `latest.json` 格式錯誤 | 不顯示 | 同上 |
| 下載或驗證失敗 | — | 顯示原因與 Release 頁面連結 |

## 6. 要保存的狀態

| 欄位 | 說明 |
|---|---|
| `last_check` | 上次成功檢查的時間 |
| `latest` | 上次看到的最新版本 |
| `skipped` | 略過的 `主.次`（沒有時為空） |
| `auto_check` | 是否自動檢查（預設 true） |

存放位置照各 app 的設定檔慣例。

## 7. 實作

| 類型 | 用什麼 |
|---|---|
| 原生 Rust | `crates/zoo-update`：`latest.json` 解析、版本比較、提示規則、簽章與 sha256 驗證。HTTP 與畫面由 app 自己做 |
| Tauri | `tauri-plugin-updater`：`endpoints` 設成上面的網址、`pubkey` 設成共用公鑰。提示規則照第 3 節在前端實作 |
| Docker（Go） | 伺服器端照第 1–3 節檢查，網頁的管理頁顯示提示；**不自動更新**，按「更新」顯示更新指令（`docker compose pull && docker compose up -d`）與 Release 頁面連結 |

## 8. 公鑰

所有專案共用一組金鑰（見 [SIGNING.md](SIGNING.md)）。app 內建「目前的公鑰」與「下一把公鑰」，任何一把驗證通過即可，換金鑰時舊版 app 不受影響。
